# چک‌لیست سریع بررسی سئوی صفحه وردپرسی/المنتور

این فایل رو به هر چت جدید بده، بعد فقط URL صفحه مورد نظر رو بگو.

## مرحله ۱ — Discovery
- [ ] robots.txt
- [ ] Sitemap مرتبط
- [ ] HTML خام صفحه (فایل .html واقعی، نه متن استخراج‌شده)
- [ ] نتیجه Rich Results Test (متن دقیق هر warning/error)
- [ ] PageSpeed Insights Mobile: ۴ امتیاز + LCP/FCP/SI/CLS/TBT + Insights قرمز/زرد + Diagnostics + Accessibility errors

## مرحله ۲ — تحلیل HTML خام
- [ ] Title یکتا و تکراری نیست
- [ ] Meta description یکتا، ۱۵۰-۱۶۰ کاراکتر
- [ ] Canonical خودارجاع
- [ ] og:*/twitter:* درست، og:image:alt واقعا مرتبطه (نه کپی‌پیست از پروژه دیگه)
- [ ] Schema JSON-LD: تکراری/خالی نیست، تاریخ‌ها ISO 8601، نوع محتوا درسته (Product فقط برای کالا، نه خدمت)، legalName/نام‌ها واقعین
- [ ] یک H1، بدون پرش سطح heading (المان‌های تزئینی نباید heading باشن)
- [ ] درصد alt گمشده عکس‌ها (الگوی «اسم پروژه - آدرس» برای نمونه‌کار قابل قبوله)
- [ ] نام فایل عکس‌ها توصیفیه
- [ ] عکس LCP لیزی‌لود نشده

## مرحله ۳ — PageSpeed
- [ ] CLS بالا → width/height صریح رو تگ img (نه CSS)
- [ ] LCP بالا → عکس هیرو: لیزی نه، فشرده، WebP/AVIF
- [ ] Render-blocking → Delay JS + Optimize CSS تو کش‌پلاگین
- [ ] SI بالا → بعد از حل render-blocking دوباره تست کن
- [ ] عکس هنوز سنگین بعد از webp → چک رزولوشن واقعی vs سایز نمایشی (نه فقط حجم فایل)
- [ ] ۳-۵ بار تست بگیر، میانگین/روند رو ملاک بذار نه یه عدد

## مرحله ۴ — Accessibility
- [ ] main landmark (Page Layout المنتور یا role="main" دستی)
- [ ] ترتیب heading (فقط گپ واقعی رو پیدا کن، بقیه رو دست‌نخورده بذار)
- [ ] کنتراست رنگ (حداقل 4.5:1)
- [ ] لینک‌های بدون نام → aria-label
- [ ] Skip link فوکوس‌پذیر (معمولا سطح قالب)

## مرحله ۵ — جمع‌بندی
- [ ] جدول قبل/بعد
- [ ] چی حل شد / چی مونده و چرا
- [ ] اولویت‌بندی: فوری (title/schema/alt) → سرعت (render-blocking/عکس/فونت) → accessibility

## اشتباهات رایج که نباید تکرار بشن
- از روی متن استخراج‌شده (نه HTML خام) نتیجه نگیر درباره canonical/og/schema
- الگوی alt نمونه‌کار «اسم - آدرس» رو مشکل ندون
- وقتی یه heading خطا داد، همه heading های مشابه رو عوض نکن — فقط گپ واقعی رو پیدا کن
- برای CLS، width/height رو درصدی نده — باید پیکسلی و واقعی فایل باشه
- به یه تست PageSpeed تنها اعتماد نکن، خصوصا SI
- تکرار اجباری کلمه کلیدی (شمارش‌محور) توصیه نکن — intent معنایی مهم‌تره
- یه alt یکسان رو روی همه عکس‌ها نذار
- Product schema رو برای خدمت استفاده نکن
